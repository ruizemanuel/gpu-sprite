# Architecture

## Contract

`generate(seed, options?)` returns `{ width: 16, height: 16, pixels: Uint8Array }`. `generate(seeds, options?)` returns one sprite per seed, in order. Both use one shared internal generator per backend. Seeds are safe integers reduced modulo 2^32 (negative seeds wrap as two's complement); anything else throws. At most 4,096 seeds per call (`MAX_BATCH`).

`defineGenerator({ backend })` returns a `Generator` that keeps a CPU model and, lazily, a WebGPU device with its pipeline and buffers resident between calls. `generateMany(seeds)` returns `{ sprites, backend, adapter? }`, reporting the backend that actually ran. `fromLatent(z)` decodes a 32-float latent. `dispose()` releases the device and makes the generator unusable.

## Seed to latent

`packages/core/src/seed.ts` and `packages/training/seed.py` implement the same function: xorshift32 (shifts 13, 17, 5) seeded with the 32-bit seed (0 is remapped to 0x9E3779B9); each of the 32 latent dimensions is the sum of twelve uniforms in [0, 1) minus 6, stored as float32. Only integer operations, additions and one division are used, so both languages agree bit for bit; `packages/core/test/fixtures/seed-vectors.json` pins 16 seeds. `SEED_VERSION` is 1 in both files and in the model spec.

## Model representation

`packages/core/src/model/weights.ts` is generated by `packages/training/export.py`. It holds the layer list (`in`, `out`, `activation`, per-tensor int8 `scale`, float32 `bias`) and one base64 payload with every weight matrix concatenated row-major `(out, in)`. `decode.ts` turns it into float32 layers, `w = fround(q * scale)`, once per page; every generator shares the decoded layers.

## CPU runtime

`cpu.ts` evaluates each dense layer with a float32 accumulator starting at the bias and summing `fround(w * x)` sequentially over inputs, then ReLU except on the last layer. `quantize.py:forward_sequential` performs the identical sequence in numpy to produce the parity fixtures.

## Decoding logits into sprites

`sprite.ts:logitsToSprite` sets a pixel when its logit is > 0, then clears every foreground pixel that has no foreground pixel among its 8 neighbours. The cleanup is one pass over the thresholded image (it does not cascade) and treats pixels outside the grid as background. `packages/training/sprite.py` (`despeckle`, `logits_to_sprites`) does the same in numpy; evaluation, the quality gate and the parity fixtures all use it. Decoding always runs on the CPU, for both backends.

## WebGPU runtime

`shader.ts` holds one WGSL compute shader for a dense layer: workgroup size 256, one workgroup per batch item, thread `o` computes output unit `o`, so no layer may be wider than 256. `webgpu.ts` creates one pipeline and, per layer, uploads weights and biases once and allocates a 16-byte uniform (`batch, inDim, outDim, activation`). A call writes the latents into the input buffer, records one compute pass with one dispatch per layer (hidden layers alternate between two activation buffers, the last layer writes a logits buffer), copies the logits into a `MAP_READ` buffer and awaits a single `mapAsync`. Buffers grow to the largest batch seen and are never shrunk. Calls on one instance are chained so buffer reuse is safe. The GPU returns logits; the CPU decodes them, which also lets the parity test compare logits directly.

The original design called for one generated shader per layer; a single dense-layer shader with per-layer uniforms does the same with less code.

## Backend selection

`auto` (the default) uses WebGPU when the batch has at least `AUTO_WEBGPU_MIN_BATCH` (64) seeds, `navigator.gpu` exists and a device can be created; otherwise the CPU. Explicit `webgpu` rejects if WebGPU is unavailable and never falls back. `fromLatent` always runs on the CPU. The measured CPU/WebGPU crossover is recorded in [MODEL_CARD.md](MODEL_CARD.md).

## Training and supervision

`data.py` downloads Kenney's 1-Bit Pack (pinned URL and sha256), checks that the sheet is 1-bit and slices it into 16×16 tiles. It keeps only the tiles inside the `include` index ranges of `data/manifest.json` (the characters-and-creatures family; without an `include` list, the whole sheet), then drops empty and full tiles and the curated `exclude` ranges, deduplicates under horizontal flip, splits by tile hash (sha1 of the canonical tile, one bucket in ten goes to validation) and augments with flips. It writes `train.npy`, `val.npy` and `stats.json`, with the counts (`total_tiles = kept_after_filter + excluded + not_included`) and the data-derived gate thresholds: the share of sprites with at most two connected components among all the real sprites of the dataset (training and validation, raw pixels), and the training density p1/p99.

`train.py` fits a VAE (encoder 256 → 128 → 64 for the latent mean and log-variance, decoder 32 → 128 → 256) with BCE + β·KL (the shipped model uses β = 4), a linear β warm-up and Adam, on one CPU thread, keeping the epoch with the lowest validation reconstruction loss. `--objective gan` trains the same decoder as a GAN generator instead; it exists as a fallback and has not been promoted.

`evaluate.py` quantizes the decoder to int8 and runs the gate from `metrics.py` on the final decoded sprites of seeds 0–999, plus the validation reconstruction accuracy against a floor keyed to the dataset: the floor recorded in `active/report.json` when that report's training and validation sha256 match the current arrays, otherwise (a new dataset) the measured accuracy minus 0.01, as a first promotion. `export.py` refuses to write the shipped weights unless the gate passes, and records the report, the parity fixtures (64 seeds) and the hashes under `packages/training/active/`. `export.py --skip-gate` writes a candidate elsewhere and refuses to write inside `packages/core/src`.

## Tests

- Node (`pnpm test`): seed contract, decoding and CPU parity against `active/parity.json`, public API behaviour.
- Python (`pnpm test:py`): seed contract, dataset pipeline, training, metrics, quantization, decoding and export.
- Browser (`pnpm test:browser`): `packages/core/test/browser/parity.ts` loads the test bundle into Chromium through Playwright and compares WebGPU with the CPU on the 64 parity seeds. WebGPU needs a secure context and Chromium does not treat `about:blank` as one, so the page is served from `http://localhost/` by request interception, without a server. Chromium is tried headless, then headed; `--swiftshader` selects the software adapter and the output says so. `apps/website/test/smoke.ts` builds the demo, serves it with `vite preview` and drives it.
- Benchmark (`pnpm --filter gpu-sprite bench:browser`, not part of `pnpm check`): times `generateMany` on both backends for batch sizes 1 to 4,096 in the same Chromium setup (`test/browser/launch.ts`) and prints the crossover.

## Size

`pnpm build:core` bundles `src/index.ts` with esbuild into `dist/gpu-sprite.min.js`. `pnpm size` Brotli-compresses it (quality 11) and fails if the result reaches 40,000 bytes; it also writes `size.json` for the demo footer. Weights dominate; the levers are the hidden width and the quantization bit depth.

## Demo

`apps/website` is a Vite page that renders a 32×32 grid of sprites from consecutive seeds, with a CPU/WebGPU toggle that is enabled only after a 64-seed parity check between the two backends passes on load, and a detail panel with 32 latent sliders that re-decodes the selected sprite through `fromLatent`.
